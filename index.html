    MacOS 多网卡分流与'位置'选项配置

    macOS 双网卡分流与多位置无缝切换配置手册

    通过 MacBook 位置选项卡，配置两种场景下的流量分配（内网，外网，国内网站）：

    • 工位场景
    • 外出场景

    1. 适用场景与配置目标

    • 工位场景： MacBook 插入网线连接内网（无外网），同时连接 Wi-Fi（有外网并开启代理）。目标是内网、外网同时畅通，不需要频繁手动开关代理或修改浏览器设置。
    • 外出场景： MacBook 只连接外网 Wi-Fi，通过 VPN（如 Clash 等）访问公司内网。目标是内网流量顺利走 VPN，外网正常访问。

    2. 环境准备（核心参数记录）

    在开始配置前，请确认并记录以下参数（本手册以您当前使用的实际参数为例）：

    参数项 示例 说明
    有线网网关 10.156.112.254 通过设置 -> 网络 -> 有线网卡「TCP/IP」详情中的“路由器”地址得到
    内网网段 10.208.0.0/16, 10.156.0.0/16 内网服务器的 IP 范围（其他网段可以按需添加）
    有线网卡系统服务名称 "USB 10/100 LAN" 通过终端运行 networksetup -listallnetworkservices 获得
    外网代理端口 依据您连接外网的 APP 自行配置（如Clash默认是 7897） 代理软件所占用的 HTTP/HTTPS/SOCKS 端口（三者有可能端口号不同）

    3. 配置步骤一：创建并配置“工位”网络位置

    步骤 3.1 创建“工位”位置

    1. 打开 Mac 的 「系统设置」 -> 点击左侧的 「网络」。
    2. 点击右侧列表下方（或底部的三个点） -> 选择 「位置」 (Locations) -> 「编辑位置…」。
    3. 点击 「+」 按钮，新建一个名为 「工位」 的位置，点击 「完成」。
    4. 点击左上角  苹果图标 -> 「位置」 -> 切换到 「工位」。

    步骤 3.2 调整服务顺序（Wi-Fi 优先）

    1. 在 「网络」 设置页面，点击右侧下方的 「三个点 (更多)」 按钮。
    2. 选择 「设置服务顺序…」。
    3. 将 「Wi-Fi」 拖动到最顶部（排在有线网卡之上），点击 「好」 。

    步骤 3.3 配置 Wi-Fi 代理与严格忽略名单

    1. 点击 「Wi-Fi」 -> 点击 「详细信息…」 -> 切换到 「代理」 标签页。
    2. 开启您的 HTTP、HTTPS、SOCKS 代理，填入您代理 APP 的端口。
    3. 滚动到最下方，在 「忽略这些主机与域的代理设置」 中，填入内网忽略规则： ⚠️ 格式要求：必须全部为英文逗号 , 分隔，中间绝对不能有任何空格，否则 Safari 可能会忽略整行规则。
    4. 点击 「好」。

    步骤 3.4 检查有线网卡代理

    1. 点击 「有线网卡（以太网）」 -> 点击 「详细信息…」 -> 切换到 「代理」。
    2. 确保其所有代理开关处于 关闭 状态（或者填入与 Wi-Fi 相同的忽略名单），点击 「好」。

    4. 配置步骤二：创建并配置“外出”网络位置

    步骤 4.1 创建并切换到“外出”位置

    1. 在网络设置的 「位置」 编辑中，点击 「+」 新建一个名为 「外出」 的位置。
    2. 点击左上角  苹果图标 -> 「位置」 -> 切换到 「外出」。

    步骤 4.2 调整服务顺序（Wi-Fi 优先）

    • 同样在网络设置中，点击右下角 「三个点 (更多)」 -> 「设置服务顺序…」 -> 确保 「Wi-Fi」 处于最顶部。

    步骤 4.3 配置 Wi-Fi 代理（不忽略内网网段）

    1. 点击 「Wi-Fi」 -> 点击 「详细信息…」 -> 切换到 「代理」。
    2. 开启您的 HTTP、HTTPS、SOCKS 代理，填入外网代理端口。
    3. 滚动到最下方，保持「忽略这些主机与域的代理设置」为空白（或者仅保留默认的 *.local,169.254/16，不要写入公司的 10.208... 等网段）。
    4. 点击 「好」 保存。

    5. 日常使用与切换指南

    配置完成后，您在日常使用中只需进行极简的一键切换，无需再进入深层设置：

    • 当在工位时：
      点击左上角  -> 「位置」 -> 选择 「工位」。
      (此时：Wi-Fi 代理生效且忽略内网，内网流量通过物理静态路由走有线网卡，内外网同时畅通)
    • 当 外出时：
      点击左上角  -> 「位置」 -> 选择 「外出」。
      (此时：无静态路由，代理没有忽略内网限制，内网流量可顺利走您的 VPN 网络)

    6. 排查与注意事项

    1. iCloud 专用代理冲突： 如果 Safari 依然打不开网页，请前往「系统设置」->「Apple 账户」->「iCloud」-> 确认 「专用代理」 (Private Relay) 处于关闭状态。
    2. Safari “隐藏 IP 地址”： 请确保在 Safari 的「设置」->「高级」->「隐私」中，已关闭 「隐藏 IP 地址」 (Hide IP address) 选项。
    3. 空格敏感： 系统代理设置最下方的忽略名单，如果存在空格（如 *.local, 10.208...），Safari 会因解析格式错误而选择不应用该名单，请务必保证无空格。

    OS笔记

    OS组织与系统调用（FRANS）

    • 设计操作系统这一层的一个目的是为了同时运行多个应用程序——并发

    Isolation 隔离性

    • 隔离性是设计OS组织结构的驱动力

    • 使用内核态和用户态，隔离OS内核和用户应用程序

    • 系统调用：用户态程序能够转换到内核态执行的方法

    • 如果操作系统没有隔离性，或者说没有操作系统这个东西，比如说Shell中的某个函数有一个死循环，那么Shell永远也不会释放CPU，进而其他的应用程序也不能够运行，==甚至都不能运行一个第三方的程序来停止或者杀死Shell程序==。所以Multiplexing（多进程同分时服用）都无法实现 -> 隔离是并发的前提

    • 另一个方面说明“隔离是并发的前提”：如果内存中不进行隔离，没有边界，那么当前程序的数据很有可能存到其他应用程序的地址上去，覆盖其他程序内存中的数据

    • 操作系统不是直接将CPU提供给应用程序，而是向应用程序提供“进程”，==进程抽象了CPU==，这样操作系统才能在多个应用程序之间复用一个或者多个CPU

    • ==exec抽象了内存==。当我们在执行exec系统调用的时候，我们会传入一个文件名，而这个文件名对应了一个应用程序的内存镜像。内存镜像里面包括了程序对应的指令，全局的数据。

    Pin对ELF/二进制的抽象模型

    概述

    • IMG = 一个被加载的 ELF 文件
    • SEC = 这个 ELF 里的一个 section（Pin 视角）
    • RTN = Pin 认为的“函数 / routine”（RTN 并不是“从反汇编自动识别出来的函数”，而是 Pin 能确认的“例程”，它的来源高度依赖符号信息）

    IMG

    • 和 /proc/self/maps 里的“一个文件映射”是同一个层级的概念

    • ==注意：映射和加载的区别==

      • 映射的时机是在进程启动exec()时，OS内核会读取文件的头部信息（如 PE 或 ELF 格式），确定代码段、数据段的大小，然后在虚拟地址空间里建立好映射关系。OS在进程的虚拟内存中“划地皮”，告诉进程：“从地址 A 到地址 B 这块区域，对应的是硬盘上某个可执行文件的第 X 字节到第 Y 字节。”此时，物理内存（RAM）里可能一字节的数据都没有

      • 加载的时机是OS如果真正执行到某段代码时，发现这一段代码或者是访问某个变量，发现这段代码or这个变量在在对应的物理内存中RAM不存在，Page Fault 时，OS才会真正把那一页数据从磁盘换到内存RAM里，这就是所谓的“延迟加载”。

      • 虚拟的好处：可以共享部分内存，比如多个进程可以把各自的虚拟地址空间“映射”到物理内存中同一份可执行代码上；映射允许操作系统设置权限；允许程序的大小超过物理内存的限制。
